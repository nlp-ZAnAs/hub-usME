# 第 6 周作业 · 三种分类方式的对比实验

数据接入与分流里的最小闭环：**同一批干净验证样本 → 三种方法 → 同一套指标 → 一张对比图**。

## 一、这个作业在验证什么

课件把分类方法排成六级阶梯（L0 规则 → L1 传统 ML → L2 小模型微调 → L3 Prompt → L4 大模型微调 → L5 系统组合）。
本作业先落地前三层，用一组**只动方法、不动数据**的受控实验回答三个问题：

1. **效果**：规则法到底能到多少？TF-IDF 离 BERT 差几个点？差在哪些类上？
2. **成本**：为了这几个点，多花多少训练时间、多少显存、多少磁盘？
3. **长尾**：15 类不均衡（23×），哪一类被整类吃掉？

## 三、怎么跑

```powershell
# 一键（推荐）
powershell -ExecutionPolicy Bypass -File .\run_all.ps1

# 或者逐步
python config.py                      # 0) 自检：检查数据与预训练模型路径
python classify_rule.py --n 500       # 1) 规则，秒级
python train_tfidf.py --n 500         # 2) TF-IDF，约 10 秒
python train_bert.py --n 500 --epochs 3   # 3) BERT，约 25~30 分钟（GPU）
python plot_compare.py                # 4) 出图
```

常用开关：

| 脚本 | 开关 | 作用 |
|---|---|---|
| 三路通用 | `--n 0` | 在全部 8,901 条干净样本上评测（默认 500 条，与课件口径对齐） |

| train_bert | `--eval_only` | 只加载已有 ckpt 重新评测，不重训 |
| train_bert | `--max_steps 30 --no_save` | 冒烟：只验流程，不落盘 |

## 四、指标口径（四种方法必须用同一套函数才算可比）

| 维度 | 指标 | 采集方式 |
|---|---|---|
| 准确率 | Accuracy / **Macro-F1** / 主题组准确率 | `metrics.classification_report`，15 类显式 `average="macro"` |
| 长尾 | per-class recall + 混淆矩阵 | 同上，按类输出 |
| 可信度 | ECE | `metrics.expected_calibration_error`（规则法无概率，不计） |
| 耗时 | 训练秒 / 单条 ms / 批量 ms / 吞吐 | `resources.Timer` + 中位数延迟 |
| 资源 | 模型文件 MB / 进程峰值 RSS / GPU 峰值显存 | `resources.ResourceMonitor`（0.2~0.5s 采样） |
| 参数量 | n_params | BERT 全参；TF-IDF = 15×F + 15 |

**评测集口径**：TNEWS 验证集先剔除与训练集完全重复的 1,099 条（11%），再按 seed=42 抽 500 条。
不这么做的话，靠字面匹配的 TF-IDF 会「背答案」，指标虚高约 3 个点。

## 五、与课件实现的差异（为了讲清楚，故意保留的不同）

| 点 | 课件 | 本作业 | 原因 |
|---|---|---|---|
| 规则法关键词 | 只用 15 个类别名，命中率 6.6%，F1 0.072 | 每类补 3~8 个业务词，命中率约 20%，F1 约 0.22 | 证明"规则法不是完全没救，但也就到这"；命中率与 F1 的关系可以直接在图上看到 |
| TF-IDF | 默认参数 | `min_df=2` + `sublinear_tf=True`，词表 11 万维 | 短文本上更稳，且模型只有 16 MB，适合展示"小" |
| 成本采集 | 只有训练时间 | 训练时间 + RSS + GPU 峰值 + 文件大小 + 单条/批量延迟 | 作业要求"效率、耗时、占用资源"三个维度都要可视化 |

## 六、结果（500 条干净验证样本，seed=42，本机 RTX 3050 Ti Laptop 4G）

| 方法 | 层级 | Accuracy | Macro-F1 | 主题组准确率 | 覆盖 | ECE | 训练耗时 | 单条延迟 | 批量延迟 | 模型大小 | 峰值内存 | GPU 峰值 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 规则 / 关键词 | L0 | 0.222 | 0.2195 | 0.378 | 15/15 | — | 0 s | 0.004 ms | 0.004 ms/条 | 0.04 MB（脚本本身） | 317 MB | 0 |
| TF-IDF + LinearSVC | L1 | 0.522 | 0.4883 | 0.686 | 15/15 | 0.299（未校准） | 8.1 s | 0.247 ms | 0.024 ms/条 | 16.1 MB | 627 MB | 0 |
| **BERT 微调（CLS 池化）** | L2 | **0.576** | **0.5769** | **0.726** | 15/15 | 0.116 | 15.7 min | 9.25 ms | 1.304 ms/条 | 390.2 MB | 3,536 MB | 2,203 MB |

训练曲线：epoch1 → F1 0.5395，epoch2 → 0.5582，epoch3 → 0.5769（按 Macro-F1 存最优）。

### 四条可以直接写进作业的观察

1. **效果差距是「5.4 个点」，成本差距是「117 倍训练时间 + 24 倍模型体积」**
   TF-IDF 8 秒拿到 0.488，BERT 15.7 分钟拿到 0.577。这 5 个点到底值不值，取决于 QPS 与预算——低 QPS、高价值、要长尾，才选 BERT。

2. **TF-IDF 把「证券」整类吃掉了：recall = 0.00**
   BERT 在同一类是 0.60。原因不是模型不行，而是「证券」与「财经」的词面高度重叠（都出现"股/涨/公司/业绩"），线性模型只能二选一。
   → 处方：先改标签口径或补区分性特征，再谈换模型。

3. **规则法的分布很畸形：科技 recall 0.93，其余 0.03~0.20**
   关键词表里"手机/芯片/AI/技术/发布会"太宽，几乎把带公司的标题都吸进科技；而"证券/旅游/文化"几乎没有覆盖。
   → 这就是"规则只能快筛、不能分流"的具体形态；命中率 20.6% 也证明它的天花板在哪。

4. **粗粒度（4 组主题）能救回一部分分数**
   规则法在 15 类上只有 0.222，但主题组口径有 0.378；BERT 从 0.576 涨到 0.726。
   → 说明"标签体系是业务定义"：先把口径收粗，效果立刻改善，这比换模型便宜得多。

5. **置信度只有 BERT 能直接用**：ECE 0.116；TF-IDF 用 decision_function 过 softmax 的 ECE 是 0.299，
   直接用 0.8 当阈值会几乎不放行（这就是课件里「必须做温度缩放」的原因）。

## 六点五、训练技巧：类别加权 A/B（加权重 vs 不加权重）

**问题**：15 类最大/最小频次差 23 倍，不加权时交叉熵被头部类主导，尾部类容易「整类归零」。
**做法**：同一份 500 条样本、同一 seed=42、同 3 epoch、同超参，唯一变量是 `--no_class_weight` 开关。

```bash
# A 组：加权（balanced 权重，默认）→ models/bert_ckpt.pt
python train_bert.py --n 500 --epochs 3
# B 组：不加权 → models/bert_ckpt_nw.pt + outputs/bert_nw_metrics.json
python train_bert.py --n 500 --epochs 3 --no_class_weight --tag _nw
python plot_class_weight.py
```

| 口径 | 不加权 | 类别加权 | Δ |
|---|---|---|---|
| Accuracy | 0.558 | 0.576 | +0.018 |
| Macro-F1 | 0.553 | 0.577 | +0.024 |
| 主题组准确率 | 0.712 | 0.726 | +0.014 |
| ECE（越小越好） | 0.1368 | 0.1162 | −0.021 |
| 头部 5 类平均 recall | 0.564 | 0.525 | −0.039 |
| 尾部 5 类平均 recall | 0.476 | 0.636 | **+0.160** |

**怎么读这张表（这是整个技巧的重点）**：

1. **收益不在总分，在尾部**。总分只涨 2.4 个点，但尾部 5 类 recall 从 0.476 拉到 0.636（+16 个点），
   头部 5 类同时掉了 3.9 个点——这就是加权的本质：**用头部的分换尾部的分**。
2. **谁最赚**：房产 +0.25、故事 +0.23、证券 +0.20、军事 +0.19 —— 全是低频、且与相邻类词面重叠的类。
   「证券」这类上一节 TF-IDF 整类归零的问题，在这里被权重直接按住。
3. **谁最亏**：国际 −0.16、科技 −0.06、娱乐 −0.04 —— 高频类被降权后，边界样本开始往相邻类漂。
4. **ECE 顺便变好（0.137 → 0.116）**：加权让输出分布更贴合真实的先验，置信度更可用。
   （副作用：置信度阈值要重新校准，不能直接沿用上一节的 0.8。）
5. **什么时候别用**：如果业务只关心头部类、或尾部类本身极少出现（<1%），加权只会白降 Acc。
   这时优先做的是「合并口径」（第五节那条观察）而不是加权。

**和课件结论的差异要说清楚**：课件实测类别加权是「打平（±0）」，
本作业因为只用了 500 条样本（每类平均 33 条、最少的类只有个位数），
类别失衡被样本量放大，所以加权收益（+2.4 分）比课件更明显；
样本量回到 5 万级时，这个收益大概率会收敛到 0.2~0.5 个点——这正是课件说的「别指望更多」。

## 八、FAQ

**Q：`未找到本地模型` 或加载失败？**
A：改 `config.py` 里的 `BERT_PRETRAINED`，指向完整的 `bert-base-chinese` 目录（要有 `pytorch_model.bin` 或 `*.safetensors`）。

**Q：显存不够（4 GB 卡）？**
A：脚本会自动把 batch 减半重试；也可以手动 `--batch 16`。实测 bs=32、max_len=64 峰值约 2.2 GB。

**Q：数字和课件 summary 表差 1~2 个点？**
A：先确认 `--n`、`seed`、是否去重三点一致；再看规则法的关键词表不同（见第五节）。
